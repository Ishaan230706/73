# S1 prompts

Prompts drafted and carried out with Claude Code (Claude Opus 5.5) using `skills/scheme-dev/SKILL.md`.
They are word for word and in the order they were run, one prompt per commit.

## S1-01: Test file

```text
Using skills/scheme-dev, write tests/test_q3.rkt for S1 (Binary Tree Traversals) before any solution exists.

A tree is () or (value left right), a value being a number or a single-character symbol. The height of () is 0 and of a
node 1 + the larger height of its subtrees. A leaf is a node with two () subtrees. Left is visited before right.
The functions under test each end their output with a newline and use display:
- (print-inorder tree): one line, the inorder list.
- (print-all-traversals tree): three lines, the inorder, preorder and postorder lists.
- (print-height-and-leaves tree): one line, the list (height leaf-count).

Examples: t1 = (4 (2 (1 () ()) (3 () ())) (6 (5 () ()) (7 () ()))) gives (1 2 3 4 5 6 7), (4 2 1 3 6 5 7),
(1 3 2 5 7 6 4) and (3 4); t2 = (1 () (2 () (3 () ()))) gives (1 2 3), (1 2 3), (3 2 1) and (3 1);
t3 = (a (b () ()) (c () ())) gives (b a c), (a b c), (b c a) and (2 2); the empty tree gives () on every line and (0 0).

Run the solution the way the grader does: copy code/*_q3.rkt, append calls, run racket, compare standard output
exactly and require empty standard error. Add edge cases (one node, only-left, only-right, repeats, negatives,
symbols, chains of depth 100 and 10000, a chain of 100000 to expose quadratic appending) and random trees checked
against simple reference definitions in the test. Compile the solution in a language that provides only the permitted
built-ins, with negative controls for that checker. Exit non-zero on any failure, without crashing if code is missing.
```

## S1-02: my-reverse

```text
Using skills/scheme-dev, start the S1 solution file (code/<id>_q3.rkt, first line #lang racket/base) with one function,
(my-reverse lst). It returns the top-level elements of lst in reverse order, in linear time, by tail recursion with an
accumulator and without any banned built-in (reverse, append). The traversals will use it to keep their cost linear.
In the file header, state the tree representation.
```

## S1-03: inorder

```text
Using skills/scheme-dev, add (inorder tree) to the S1 file: it returns the list of values in left subtree, node, right
subtree order. Visit left before right with a named let whose accumulator holds the values seen so far, newest first;
make the visit of the right subtree a tail call; reverse once at the end with my-reverse. Linear time, no append, no
printing, and () gives ().
```

## S1-04: print-inorder (S1.a)

```text
Using skills/scheme-dev, add (print-inorder tree) for S1.a: it prints the inorder list on one line using display and
ends with a newline. Nothing else is printed and no value is returned that Racket would print at the top level.
```

## S1-05: preorder

```text
Using skills/scheme-dev, add (preorder tree) to the S1 file: it returns the values in node, left subtree, right
subtree order. Use the same accumulator pattern as inorder: cons the node's value before visiting the left subtree,
visit the right subtree as a tail call, and reverse once. Linear time, no printing, () gives ().
```

## S1-06: postorder

```text
Using skills/scheme-dev, add (postorder tree) to the S1 file: it returns the values in left subtree, right subtree,
node order. Thread the accumulator through left and then right, cons the node's value after both, and reverse once.
The visit of the right subtree cannot be a tail call here, so use plain recursion for it. Linear time, no printing,
() gives ().
```

## S1-07: print-all-traversals (S1.b)

```text
Using skills/scheme-dev, add (print-all-traversals tree) for S1.b: it prints exactly three lines with display, in this
order: the inorder list, the preorder list, the postorder list. Each line ends with a newline. Reuse print-inorder for
the first line. An empty tree prints () three times.
```

## S1-08: tree-height

```text
Using skills/scheme-dev, add (tree-height tree) to the S1 file. The height of () is 0 and the height of a node is 1
plus the larger of the heights of its left and right subtrees, so a single node has height 1. Use max. Plain
structural recursion is natural here because the result combines two recursive results.
```

## S1-09: leaf?

```text
Using skills/scheme-dev, add the predicate (leaf? node) to the S1 file: true exactly when the non-empty node has both
its left and its right subtree equal to (). The empty tree is not a leaf, so the predicate must return false for it
instead of failing in car or cdr.
```

## S1-10: count-leaves

```text
Using skills/scheme-dev, add (count-leaves tree) to the S1 file: the number of leaves, using leaf?. The empty tree has
none. Pass the running count as an argument, visit left before right and make the visit of the right subtree a tail
call. No mutation.
```
