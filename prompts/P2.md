# P2 prompts

Prompts drafted and carried out with Claude Code (Claude Opus 5.5) using `skills/prolog-dev/SKILL.md`.
They are word for word and in the order they were run, one prompt per commit.

## P2-01: Test file

```text
Using skills/prolog-dev, write tests/test_q2.pl for P2 (Form a Valid Arithmetic Equation) before any solution exists.

For a list of non-negative integers n1..nk an equation is L=R, with L over n1..nj and R over n(j+1)..nk, 1 <= j < k.
An expression is a number, or two expressions joined by + - * /. Numbers keep their order and are never joined, there
is no unary minus, sub-values may be negative, and every division must be exact with a non-zero divisor. Both sides
have the same integer value. An equation is an SWI-Prolog string with no spaces. * and / bind tighter than + and -,
all are left-associative, a left operand has parentheses only if its operator has lower precedence than its parent's,
a right operand if it has the same or lower precedence, and a number never has parentheses. Different trees count as
different equations.

The interface under test: generate_equation(List,Equation) gives one valid equation or fails (also for lengths 0 and
1); all_equations(List,Equations) gives every one, without duplicates, in sort/2 order, or []; count_equations(List,N)
gives the length of that list.

Use these examples: [4,2,5,3] gives ["4*2-5=3","4*2=5+3","4-2=5-3","4/2=5-3","4=2*(5-3)","4=2+(5-3)","4=2+5-3"];
[2,3,4] gives []; [2,4,8] gives ["2*4=8"]. Add edge cases: every parenthesis rule, inexact inner division, division by
zero, zero divided, negative dividends, no digit joining, big integers, repeated numbers, a bound Equation, an
unsolvable list of seven numbers, silence, and the bans. Take expected counts from an independent brute force, and
also check each returned equation on its own (leaves, order, exact value, canonical form). Find the solution as
code/*_q2.pl. Exit non-zero on any failure, and report a missing predicate as a failed test, not a crash.
```

## P2-02: split/3

```text
Using skills/prolog-dev, start the P2 solution file (code/<id>_q2.pl) with split(List, Front, Back): Front and Back are
non-empty and, joined in that order, give List. It enumerates each split once and fails for lists of length 0 and 1.
Both parts must be strictly shorter than List, because recursion on them has to terminate. Import only library(lists).
In the file header, explain that expressions will be trees num(N) or node(Op, Left, Right), evaluated as they are
built, with text produced only for output.
```

## P2-03: apply_op/4

```text
Using skills/prolog-dev, add apply_op(Op, X, Y, Z) to the P2 file: Z is the integer result of X Op Y for Op one of
+ - * /. Division holds only when Y is non-zero and divides X exactly, and must fail, never raise, otherwise. X and Y
may be negative or very large. Unbound Op enumerates the four operators. Z may already be bound.
```

## P2-04: expression/3

```text
Using skills/prolog-dev, add expression(Numbers, Tree, Value) to the P2 file. Tree is every expression tree over the
non-empty list Numbers with the numbers in order (num(N), or node(Op, Left, Right) built with split/3 and apply_op/4),
and Value is its integer value. Every tree appears once, trees with an invalid division anywhere do not appear, and
the search is finite. Value may already be bound.
```

## P2-05: precedence/2

```text
Using skills/prolog-dev, add precedence(Op, Level) to the P2 file as facts: * and / bind tighter than + and -, and
operators of the same kind have the same level. A higher level means tighter binding. It will decide where
parentheses are printed.
```
